# 0002. Мережа через WSAAsyncSelect в одному потоці

- Статус: прийнято

## Контекст

Застосунки мають вікна, тому мережеві події мають оброблятися в потоці інтерфейсу. Вікно не можна блокувати очікуванням даних.

## Розглянуті варіанти

1. Окремий потік на кожне з'єднання з блокувальними `recv`/`send`. Потрібна синхронізація доступу до елементів вікна.
2. `WSAAsyncSelect`: Windows сама надсилає у вікно повідомлення про події сокета.
3. Overlapped I/O з портами завершення. Документація Microsoft радить саме його замість `select`-подібних моделей, але він суттєво складніший.

## Рішення

Обрано `WSAAsyncSelect`. Усі події приходять як `kSocketMessage` у цикл повідомлень вікна, зворотні виклики виконуються в потоці інтерфейсу.

## Наслідки

- Нема власних потоків, мʼютексів і гонок за елементи керування.
- Сокет стає неблокувальним, тому `Connection` сама веде вхідний і вихідний буфери.
- Довге читання ділиться на порції (бюджет на подію), щоб вікно залишалося чутливим.
- Масштабованість обмежена: підхід підходить для невеликої кількості клієнтів, як у цій роботі.
