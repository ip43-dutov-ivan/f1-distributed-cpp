# Лабораторна робота 4 (варіант 2)

Сервер і три клієнти на Win32 та Winsock. Клієнти 1 і 2 надсилають серверу системні метрики Windows, клієнт 3 надсилає введений текст. Сервер показує все, що отримав, і може написати обраному клієнтові або відключити його.

## Вимоги

- Windows 10/11 (x64 або ARM64);
- Visual Studio з робочим навантаженням «Розробка настільних застосунків C++», стандарт C++20;
- бібліотеки `Ws2_32` та `Comctl32` підключаються через `#pragma comment(lib)`, налаштовувати нічого не потрібно.

## Збирання

1. Відкрити `CppLab4/CppLab4.slnx`.
2. Обрати конфігурацію (наприклад, Debug, ARM64 або x64).
3. Зібрати рішення. Спочатку збирається статична бібліотека `Common`, потім чотири виконувані файли, які її підключають.

## Запуск

1. Запустити `Server`, у меню `Server` обрати `Start` (порт 5000).
2. Запустити `Client1`, `Client2`, `Client3`. У кожному меню `Client` обрати `Set Connection`.
3. Адресу сервера можна передати в командному рядку (весь рядок береться як ім'я хоста), за замовчуванням це `localhost`.

У Visual Studio можна запускати все одразу: `Solution → Configure Startup Projects → Multiple startup projects`, для `Server` і трьох клієнтів поставити `Start`.

## Що робить кожен застосунок

| Застосунок | Що надсилає серверу | Команда відправки |
| --- | --- | --- |
| Client 1 | висота рядка заголовка вікна (`SM_CYCAPTION`), параметри клавіатури (`GetKeyboardType`), висота екрана (`VERTRES`) | `Client → Send Metrics`, `Ctrl+Enter` |
| Client 2 | ширина робочої області на весь екран (`SM_CXFULLSCREEN`), кількість моніторів (`SM_CMONITORS`), DPI по горизонталі (`LOGPIXELSX`) | `Client → Send Metrics`, `Ctrl+Enter` |
| Client 3 | текст, введений користувачем | `Client → Send Message`, `Ctrl+Enter` |
| Server | текст обраному у списку клієнтові | `Client → Send Message`, `Ctrl+Enter` |

## Структура репозиторію

```text
CppLab4/
  CppLab4.slnx       рішення Visual Studio
  Common/            статична бібліотека, спільна для всіх застосунків
  Server/            сервер
  Client1/           клієнт 1 (метрики)
  Client2/           клієнт 2 (метрики)
  Client3/           клієнт 3 (текст)
docs/
  architecture.md    класи, їхні обов'язки, потік подій
  protocol.md        формат повідомлень у мережі
  adr/               рішення, які впливали на архітектуру
```
